## 本轮修复

### 1. AI 选择增加确定性触发证据门

此前，工程选择上下文主要用“存在缺失字段且无显式冲突”判断选项是否可交给模型，可能使同一设备族
中的多个互斥材料/零部件路线同时显示为可选。现在每个模型建议还必须满足当前工况对登记触发条件的
确定性支持：

1. `rule_id / condition_id / axis_id / choice_id` 必须存在于冻结登记表；
2. 建议字段和值必须与登记选择完全一致；
3. 选择上下文哈希必须与当前设备输入一致；
4. 当前介质、温压、相态、腐蚀/危险性等事实必须支持该分支；
5. 不得覆盖 Aspen 或用户已经提供的值。

例如，仅有 `material=S30408` 而没有腐蚀性、极端 pH 或高氯证据时，不再允许模型把泵自动切换到
`CORROSIVE_316L_HARD_FACE`。合法 ID 但缺少触发证据的建议会被拒绝，不进入确定性重算。

### 2. 修正 S30408 工艺管道路线

S30408/06Cr19Ni10 不再错误退化到 20 钢路线。当前登记初筛会保持不锈钢材料事实，形成 S30408
管道/管件、06Cr19Ni10 法兰、304 柔性石墨垫片、A2-70 紧固件和 CF8 阀门的同材料族候选。
本轮 2.5 MPa 合成工况的程序等级候选为 `SS304-PN40-BW-CA0`。

这仍是程序管道等级候选。项目管道材料等级表、材料压力—温度额定、腐蚀裕量、法兰/垫片适用性、
焊接工艺、应力和支吊架等正式证据仍必须单独闭合。

### 3. 修正 PFD 单设备 Agent 绑定与写回

用户从 PFD 打开设备、修改参数并执行单设备重算后，最新节点结果现在会成为 Agent 的确定性基线，
同时绑定当前人工输入与来源信息。Agent 不再审核或写回先前缓存的整份 Aspen 导入结果。节点再次修改
或上下文哈希变化时，旧模型回答失效，不能覆盖新结果。

这不是只靠界面状态提示。Agent 运行前有三项硬门：当前节点必须存在有效 `selection`，来源状态必须是
`RECALCULATED_CURRENT`，保存的确定性结果哈希必须与当前选择哈希一致。改型会先使旧 Agent 基线
失效；三项任一不满足就要求重算并阻断远程调用/写回。

### 4. 加强连接与模型响应安全

- DeepSeek/OpenAI 官方 provider 使用规范官方地址；自定义地址明确走 OpenAI-compatible 路线；
- API 根地址与完整协议地址只规范化一次，避免重复拼接；
- 认证请求不跟随 HTTP 重定向，降低 Key 被转发到其他主机的风险；
- URL、Key、模型、协议、推理强度或存储设置变化后，既有连接测试和已应用设置立即失效；
- API Key 只驻留当前进程内存，不进入项目、报告、运行清单或测试输出；
- 模型响应要求唯一输出章节、受限置信度枚举和中文可见内容；解析或严格校验失败时关闭写回，不以自由文本降级冒充成功。

## 尚未闭合的功能和证据

### 不是厂家正式型号

- 泵的 GB/T 5662 标记是标准规格/参考点候选，不是任意厂家的连续 Q-H、效率、功率、BEP 和 NPSHr 曲线；
- 换热器仍需 EDR/HTRI 或同等级热工水力、振动、压降与机械设计；
- 塔器仍需塔板/填料厂家水力学、液泛、漏液、持液量、压降和传质效率保证；
- 压缩机仍需厂家性能图、喘振裕量、级间冷却、密封与驱动机闭合；
- 管道与阀门仍需正式材料等级、压力—温度额定、完整管网、应力、水锤、事故工况和厂家选型。

因此结果继续标记为 `J / provisional / TYPE_SCREENING`，未满足同设备正式证据门时不得采购、施工或报审。

### 不是生产 Aspen 全覆盖

- 较早远程 6/6 是 bridge 驱动的合成工况，不是六份生产 BKP，也不是本次完整 GUI 验收；
- 本轮两个真实 Aspen 派生案例仅本地验证，样本数量不足以代表所有 Aspen 版本、物性方法、用户模型和插件；
- 尚需在用户批准的数据边界内，用生产环境执行一次 GUI 导入、节点编辑、单设备重算、远程 Agent、报告导出和人工签收的完整验收；
- 后续审计脚本优先运行 `--tk-smoke`，先验证真实 Tk 窗口、PFD 改型、`selection + RECALCULATED_CURRENT + hash` 硬门，再消耗远程模型额度；
- v2.4.2 Windows GUI/CLI ZIP 已发布并完成远端重新下载核对；若源码集合或知识包修订变化，则必须重新构建和发布新版本，不能沿用本文哈希或覆盖现有资产。
