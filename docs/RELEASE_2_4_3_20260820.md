# v2.4.3 发布与成品核验说明

验证日期：2026-08-20

发布页：[设备设计选型系统 v2.4.3](https://github.com/milklong888/equipment-design-selector/releases/tag/v2.4.3)

## 本轮结论

v2.4.3 把五类此前只有基础候选的设备补成可追溯的专用初算链，并把 Aspen COM 提取改为注册表驱动、逐字段留痕和失败关闭。程序仍坚持工程边界：缺少厂家曲线、专业软件结果、机械校核或生产 Aspen 实测时，只输出具体的程序初筛规格和补证方案，不把它升级成可采购的厂家正式型号。

## 主要改进

### 五条专用设备计算链

- 搅拌器：混合任务/黏度驱动桨型，计算 Re、Np、轴功率、扭矩和纯扭转轴径下限；未知显式桨型、超大功率或超大釜径失败关闭。
- 静态混合器：按登记 DN/外径目录选径，校核流速、Re、元件压降和并联列数；用户锁定的 DN 若流速或压降超限，结果保持具体代号但标记不可交付。
- 膜设备：显式几何优先，卷式、管式、中空纤维和平板不再混用面积；按目标产物流量、通量、回收率和裕量计算面积、元件数、并联列和级数。
- TSA/成套设备：工艺功能决定 TSA、PSA、守护床、过滤或干燥路线；TSA 只有在容量基准带可识别物理单位且负荷/工作容量闭合时才计算床层。
- 气体膨胀机：尊重用户或 Aspen 的密度/质量流量，计算级数、功率、出口温度和保护旁路；相态、低温材料边界及单级允许压比异常会硬阻断。

五条链均输出 `calculation_id`、`formula_id`、来源引用、代入式、追溯哈希、分支代码和中文分支说明。顶层推荐、专用规格、PFD 节点、客户一览表和报告使用同一确定性结果。

### Aspen 提取覆盖与失败关闭

- 流股和已登记模块按 registry 提取，每个字段记录 path、unit、status 和 provenance。
- 未映射树默认只保存类型、长度和 SHA-256 元数据，不保存原始值；敏感内容、非有限数和超长文本被拒绝或截断。
- 覆盖数据写入独立 `aspen_extraction_coverage.json` 旁车；主 `aspen-equipment-export-v1` 保持旧合同兼容。
- Streams/Blocks 根访问失败、未知 registry identity、不可评分覆盖、组分异常、发现错误或全案例预算耗尽都会返回 `BLOCKED_COM_EXTRACTION`，且不继续设备推导。
- 两份 Aspen Schema 已进入源码和打包权威修订，缺失、清单漏项或同尺寸篡改都会失败关闭。

上述实现已通过严格 fake-tree、Schema 和打包测试，但本机没有连接真实生产 Aspen COM。不同 Aspen 版本、物性方法、用户模型、多相组分树和大型 BKP 性能仍需在生产机逐案验证。

### 输出与 GUI/Agent 一致性

- 已阻断设备仍显示程序给出的具体初筛代号、所走分支和修改建议，同时明确 `calculation_blocked`、`TYPE_SCREENING`、`formal_design_evidence=false` 和不可采购。
- 非阻断的超大换热器、塔或异常泵优先显示分台、并联/串联系统方案，而不是用单台基础代号遮住调整方案。
- PFD 改型会使旧 Agent 基线失效；重新运行 Agent 前必须同时满足当前 selection、`RECALCULATED_CURRENT` 和确定性结果哈希一致。
- AI 型式、材料和零部件选择受登记触发证据门控制，不能凭合法选项 ID 覆盖 Aspen/用户事实，也不能把自由文本变成型号。

## 不能误称为已完成的部分

- 程序具体代号是确定性初筛规格，不是厂家正式采购型号；泵仍需完整 Q-H、效率、功率和 NPSHr 曲线，其他设备也需对应厂家/专业证据。
- 换热器 EDR、塔内件水力学、压力容器机械/应力、管网水锤与应力、压缩机/膨胀机性能图仍未自动闭环。
- 生产 Aspen V14/其他版本的 registry-driven COM 提取尚未在本机实测；本次不能宣称生产环境通用兼容。
- 本次没有重新消耗用户 API Key。此前 DeepSeek 官方连接与前五条严格设备链通过，第六条及后续 GUI 测试因 HTTP 402 余额不足中断；不得写成本次远程 GUI 6/6。
- API Key 只应在 GUI 中临时输入，不应写入项目、报告、Git 或发布资产；用户此前在对话中暴露过的 Key 应轮换。
